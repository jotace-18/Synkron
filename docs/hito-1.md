## Qué falta hacer

1. Elegir las tecnologías y resolver cómo se gestionarán las cuentas (ADR-005).
2. Revisar la documentación y poder explicar una sincronización, una regla y un fallo.
3. Crear el repositorio público, elegir licencia y guardar el primer commit. Los materiales docentes y las notas internas quedan fuera.
4. Crear cinco milestones y el tablero de GitHub, con vistas por estado y milestone.
5. Publicar las historias con etiqueta `user-story`, criterios de aceptación y lista de tareas. Añadir también el trabajo documental pendiente.
6. Añadir los enlaces reales de GitHub y comprobar navegación y diagramas.
7. Revisar los requisitos del enunciado y preparar la entrega.

El [procedimiento oficial](https://github.com/cvillalonga/CC-26-27/blob/main/entregas/README.md) utiliza un fork del repositorio docente y un PR que modifica solo la fila asignada en `entregas/entrega1.md`. Ese fork es distinto del repositorio de Synkron.
